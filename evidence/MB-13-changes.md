# MB-13 tracked changes — 2026-11-11

Implemented a durable checkpoint SQLite store and content-hashed blobs under the app state directory, capturing direct file.write/file.edit before and after effects. Remote tools and the Changes tab list records and display bounded text diffs; binary/non-UTF-8 snapshots are retained without pretending to show a text diff. Current tracked file limit is 1 MiB, aligned with the file API.

Restore checks conversation/root identity and the current whole-file hash against the captured after state. A later owner edit causes a conflict. Restoring a created file removes only that unchanged tracked result. Restoring an original file publishes its earlier bytes atomically. A retry after publication but before the metadata receipt recognizes the original state rather than duplicating work. Pending snapshots remain explicitly unavailable for restore. Root/link changes, escapes and the app's private store are refused.

The helper model supplied the standalone engine/tests; root reviewed bounded reads/root identity, integrated the router/policy and built the Changes UI. Tests cover create/modify/delete engine state, later-owner conflict, wrong chat/root, reopen, interrupted snapshots, restore receipt loss and size/path boundaries. The UI test restores through the actual common policy and refuses owner conflicts. Symlink fixtures are skipped on this Windows account where link creation is unavailable.

Actual Muse produced four checkpoints during the disposable expansion probe; independent file checks passed. The isolated renderer produced `.local/visual-review/changes.png`, which was visually inspected. Byte-compare checks narrow races with unrelated concurrent writers but are not a filesystem-level compare-and-swap guarantee. This pass does not provide whole-run atomic rollback, shell/Git snapshots, metadata/ACL restoration or undo of external effects; MB-19 and broader recovery remain separate work.
