# Functional harness implementation — 2026-11-11

Owner requested investigation/development with the root as orchestrator and up to two a helper model agents concurrently. Scope includes separate conversations, projects and goals/planning; functional behavior precedes visual polish. Owner authorized app restart for testing.

## Reuse and delivered components

- Unchanged pinned official Muse SDK: pairing crypto, Noise/Link, chat, turn tracking and voice. Windows lifecycle/storage adapted locally.
- DSH architectural references: durable session/event records, explicit tool contracts, cancellation, persistence and bounded goal progression. No DSH fork/runtime or second local model loop.
- SQLite projects/conversations, distinct remote Muse session IDs, project guidance/root AGENTS.md, independent persistent drafts/transcripts, plans/goals and send outcomes.
- Bounded file read/search, whole-file checksums for editable files, stale-hash refusal, unique edits and atomic writes. Selected roots are mistake containment, not a sandbox.
- Windows suspended process launch into kill-on-close Job Objects; journaled admissions, request-ID dedup, 4-job cap, timeout/cancel, bounded output pages and restart ambiguity.
- Goal controller using pinned MuseTurn/ReplayScope, explicit start, acknowledged terminal events, bounded rounds and no blind replay/startup autorun.
- Established Playwright/Chromium with per-conversation isolated contexts, page text/control inspection, navigation/fill/click and screenshot artifacts.
- Established pywinauto UIA and Win32 session/idle/integrity/foreground checks; window/control observation, focus/invoke/edit and screenshot artifacts.
- Separate voice-only SDK connection, same conversation, default PC audio, mute/interrupt/hangup. Normal control registration is retained.

Sources inspected: [DSH architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md), [tools](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/tools.md), [sessions](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session.md), [Playwright contexts](https://playwright.dev/python/docs/api/class-browsercontext), [pywinauto UIA](https://pywinauto.readthedocs.io/en/latest/getting_started.html) and vendored SDK source. ## Remaining acceptance

- Screenshot artifacts are local; automatic model vision from them is not implemented. Browser contexts are temporary and separate from the user's signed-in profile.
- Jobs have the user's Windows permissions. Local plan/context data guides Muse but does not replace its remote internal runtime.
- QoL/visuals, public packaging, unattended startup and general external MCP/plugin hosting remain later work. This is a functional development baseline, not a claim that every acceptance criterion is finished.
