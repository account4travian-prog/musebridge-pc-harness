# MB-01 / MB-02 implementation receipt — 2026-11-11

Owner authorized implementation and planned flashing in this chat. This receipt records local evidence only. No board was attached at the last enumeration (zero COM ports), no flashing was attempted, and no live Muse account/session was accessed.

## Delivered

- Native PySide6 Windows window, background asyncio connection core, main-chat send/subscribe and bounded transcript updates. Send failures are not automatically replayed. Window close requests connection shutdown. No startup service/task or local listening endpoint.
- Protected identity, pairing and SDK-token storage using Windows user-bound DPAPI; atomic replacement. Single-instance application lock.
- Upstream pairing/Noise/Link modules reused unchanged from SDK commit `9d8cca156cdec9ea06efcf854b03dccc5ca76d42`. No Linux executor/service/BlueZ import in the host path. The initial registration keeps the upstream documented platform envelope for compatibility; health/tool descriptions explicitly identify Windows.
- Serial BLE transport with boot/connection generation checks, bounded framing, fragmented serial reads, packet ACKs and keepalive. Official SetupController/PairingSession own crypto and credential verification.
- Independent ESP32-S3 Arduino/NimBLE bridge firmware. Fixed setup UUIDs match the SDK. It uses UART0, no Wi-Fi/PSRAM/LED assumptions. Advertises only after host configuration and stops after host timeout.
- Only `bridge.health` is advertised initially. Shell, file editing, voice and desktop tools remain unbuilt, deliberately sequenced after the live pairing/chat proof.
- Launch script, locked Python environment, running instructions and firmware procedure.
